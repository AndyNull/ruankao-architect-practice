# 系统架构设计师练题台

面向软考高级资格考试的开源刷题站，支持系统架构设计师、系统规划与管理师、信息系统项目管理师、系统分析师和网络规划设计师。覆盖综合知识、案例分析和论文，基础练习无需后端。

完整变更见 [CHANGELOG.md](CHANGELOG.md)。

## 主要功能

- 五科题库、作答、错题、收藏、统计和论文范文按科目隔离。
- 选择题直接判题，展示参考答案、来源、题库原解析与本地 AI 解析。
- 案例保留背景、子问题及参考答案，同时提供本地解题思路。
- 论文支持按题生成 AI 范文，保存后可重新阅读、生成或删除。
- 章节进度、模块正确率与薄弱项统计帮助安排复习。
- 资料页提供考试大纲和教程阅读，适配桌面与移动端。

## 在线使用

[打开练题台](https://andynull.github.io/ruankao-architect-practice/)

## 本地运行

Windows 可双击 `start.cmd`，也可执行：

```bash
node scripts/serve.mjs
```

访问 `http://localhost:4173/`。不要直接打开 `index.html`，`file://` 无法正常加载模块和题库。

## 使用方式

1. 顶部选择考试科目，再选择练习模式。
2. 点击选项直接判题；需要重看已答题时使用题库浏览、错题或复习模式。
3. 右侧答题卡按 75 题分段，可翻页或跳转题目；真题套卷模式可选择考试期与批次。
4. 点击 `收藏本题` 保存重点题；展开章节进度查看模块完成情况。
5. 案例页阅读参考答案和解题要点，论文页可主动生成范文。
6. 顶部导入或导出进度 JSON，导入时先查看摘要，再确认替换本地进度。

## 练习模式

| 模式 | 用途 |
|---|---|
| 继续练习 | 按题库顺序继续，只包含未作答题 |
| 记忆复习 | 错题和到期题优先，默认最多 20 题，可调整数量 |
| 章节练习 | 按模块集中练习 |
| 真题套卷 | 按年份、考试期和批次选择已导入试卷 |
| 错题重刷 | 练习最近一次仍答错的题 |
| 收藏题 | 重刷手动收藏的题目 |
| 题库浏览 | 按来源、年份、模块、状态与关键词筛选 |

## 资料与图题

资料目录位于 `data/study-materials.json`，正文保存在 `data/study-materials/`，按需加载，并保留原始来源链接。桌面采用目录与正文双栏，移动端切换为单栏。

图题结构保存在 `data/figures.json`，结构化重绘标注“非原卷图”。原题引用图片但尚未获得可靠结构时显示“原图待补录”，不臆造连线或数值。

## AI 解析与范文

接口为 `https://glm.996986.xyz/v1/chat/completions`，模型为 `glm-5.2`。如接口需要鉴权，可在数据页填写 API Key，密钥只保存在页面内存。

- **选择题**：优先展示与题目签名匹配的本地解析；答错后可主动重新解读错因，支持流式展示与完整响应恢复。
- **案例**：原参考答案与 AI 解题要点分别保留；AI 内容用于复习补充，不替换原答案。
- **论文**：生成内容明确标为 AI 范文示例，摘要约 300–400 字、正文约 2000–3000 字，围绕题目要求与本人项目职责展开。
- **保存**：范文通过结构、篇幅与项目角色校验后才自动保存；不合格内容可保留为草稿，不覆盖已合格范文。
- **诊断导出**：数据页可下载 `ai-diagnosis.json`，包含作答轨迹、模块统计、收藏和错题材料，供阶段复盘。

## 进度与隐私

作答、收藏及已保存范文保存在本机浏览器 IndexedDB。基础练习读取本地解析，不自动请求 AI；主动重解读、案例整理或范文生成时，才向配置的 AI 接口发送对应题目材料。

进度 JSON v2 包含全部科目的作答、收藏和论文范文。导入兼容 v1/v2，确认后替换本地进度。清空作答记录不会删除已保存范文，也不影响已导出的 JSON。项目不提供在线人数统计，不额外上报访问或答题进度。

## 维护与 GitHub Pages

题库重建与本地解析更新：

```bash
node scripts/build_subject_banks.mjs
node scripts/build_local_subject_explanations.mjs
```

补充导入及 AI 批量生成脚本位于 `scripts/`；需准备相应原始资料。测试和日志仅保留本地，不提交或部署。

在仓库 Settings → Pages 中选择 `GitHub Actions`。推送 `main` 或手动运行 `Deploy to GitHub Pages` 即可发布。工作流 `.github/workflows/pages.yml` 仅上传页面、源码及运行数据，无需后端。
